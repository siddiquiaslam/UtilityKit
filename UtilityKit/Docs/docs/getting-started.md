# Getting started

This guide shows the quickest way to start using UtilityKit in a .NET project, plus instructions for building the library locally and running tests.

## Prerequisites

- .NET SDK (recommended: .NET 6, .NET 7, or later)
- A code editor (Visual Studio / VS Code / Rider)
- Optional: docfx to build documentation locally

## Install via NuGet

The package on NuGet is published as `UtilityKit`. Replace `x.y.z` with the version you want to use.

dotnet CLI
```bash
dotnet add package UtilityKit --version x.y.z
```

PackageReference
```xml
<PackageReference Include="UtilityKit" Version="x.y.z" />
```

If you want to depend on the local project during development, add a project reference instead of the package.

## Quick usage examples

Add the namespace (actual types may vary — check the API reference produced by DocFX):

```csharp
using UtilityKit;

public class QuickExamples
{
    public void Run()
    {
        // 1. Safe string helpers
        string input = "  hello ";
        var trimmed = StringHelpers.TrimOrNull(input); // "hello"

        // 2. Guard helpers: argument validation
        Guard.NotNull(input, nameof(input));

        // 3. DistinctBy: collection helper (LINQ-style)
        var users = new List<User> { /* ... */ };
        var uniqueByEmail = users.DistinctBy(u => u.Email).ToList();

        // 4. Date/time helper: get UTC ISO string
        var nowUtcIso = DateTime.Now.ToUtcIsoString(); // e.g. "2026-01-09T12:34:56Z"

        // 5. JSON helpers
        var json = JsonHelpers.Serialize(users);
        var deserialized = JsonHelpers.Deserialize<List<User>>(json);
    }
}
```

Note: The examples above demonstrate typical usage patterns. Consult the API reference for exact type and method names available in the version you install.

## Add to a project (example)

Create a new console app and add UtilityKit:

```bash
dotnet new console -n MyApp
cd MyApp
dotnet add package UtilityKit --version x.y.z
```

Use helpers:

```csharp
using UtilityKit;

Console.WriteLine(StringHelpers.TrimOrNull(" sample "));
```

## Build from source

If you want to build UtilityKit locally or contribute, follow these steps:

1. Clone the repository:
```bash
git clone https://github.com/siddiquiaslam/UtilityKit.git
cd UtilityKit
```

2. Restore dependencies and build:
```bash
dotnet restore
dotnet build -c Release
```

3. (Optional) Create a local NuGet package:
```bash
dotnet pack -c Release -o nupkg
```
You can then install the generated `.nupkg` into your projects or publish to a local feed.

## Run tests

Unit tests are included in the repository (if present). Run them with:

```bash
dotnet test
```

If tests require specific runtimes or environment variables, check the test project's README or the repository's CI configuration.

## Working with specific frameworks

UtilityKit aims to target commonly used .NET frameworks (for example, `net6.0`, `net7.0`, or `netstandard2.0`) so it can be reused in libraries and apps. If you encounter compatibility issues:

- Ensure your app's target framework is compatible with the UtilityKit package version you're using.
- If building from source, inspect project files (`.csproj`) for target frameworks and adjust as needed.

## Troubleshooting

- "NU1101: Package not found" — verify the package id and version, or use a local `.nupkg` produced via `dotnet pack`.
- "Type or namespace name 'UtilityKit' does not exist" — confirm `using` statement and that the package/reference is added to the correct project.
- Platform-specific APIs — some helpers may target modern .NET runtimes. If you need legacy framework support, check the project's supported TFMs or open an issue.
